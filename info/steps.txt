Шаг 1: Создаем пользователей-служб

Заходим на сервер под root'ом и создаем пользователей без возможности интерактивного входа (без пароля и с шеллом /usr/sbin/nologin).
bash

# Создаем пользователя для управления веб-сайтами
useradd -r -s /usr/sbin/nologin -m -d /srv/web webmaster

# Создаем пользователя для сервиса глобальной библиотеки
useradd -r -s /usr/sbin/nologin -m -d /srv/global-lib glib

# Создаем пользователя для сервиса приватных облаков
useradd -r -s /usr/sbin/nologin -m -d /srv/private-cloud pcloud

# Создаем пользователя для AI-интерфейса
useradd -r -s /usr/sbin/nologin -m -d /srv/ai aiagent

Разбор параметров:

    -r: Создает системного пользователя (UID из системного диапазона).

    -s /usr/sbin/nologin: Запрещает интерактивный вход. Безопасно.

    -m -d /путь/...: Создает домашний каталог и сразу назначает его владельцем пользователя. Это идеально подходит под вашу структуру в /srv


Копируем исполняемый файл глобальной библиотеки
scp global-library-server root@178.212.13.179:/srv/global-lib/

Меняем права файла
chown glib:glib /srv/global-lib/global-library-server
chmod 750 /srv/global-lib/global-library-server

Создаем файл сервиса
nano /etc/systemd/system/global-lib.service

[Unit]
Description=Global Components Library Service
After=network.target

[Service]
Type=simple
User=glib
Group=glib
WorkingDirectory=/srv/global-lib
ExecStart=/srv/global-lib/global-library-server
Restart=on-failure
RestartSec=10
NoNewPrivileges=yes
PrivateTmp=yes

[Install]
WantedBy=multi-user.target

Запускаем
sudo systemctl daemon-reload
sudo systemctl enable global-lib
sudo systemctl start global-lib

Шаг 2: Настраиваем права на каталоги

Теперь нужно "разложить все по полочкам" и выдать правильные права.
bash

# 1. Структура веб-сайтов (управляется webmaster, читается Apache)
# Создаем подкаталоги для сайтов
mkdir -p /srv/web/{salixeda.org,salixdev.ru,salixfab.ru}

# Назначаем владельца: webmaster, группа: webmaster
chown -R webmaster:webmaster /srv/web

# Права: владелец (webmaster) может всё (7), группа (webmaster) может читать и входить (5), остальные ничего (0).
# Но! Apache должен читать файлы. Обычно Apache работает от пользователя www-data.
# Добавляем пользователя www-data в группу webmaster, чтобы он получил доступ (r-x).
usermod -aG webmaster www-data  # Даем Apache доступ к сайтам

Создаем конфиги для каждого сайта

Для salixdev.ru особый случай, так как содержит доступ к настройке почты
<VirtualHost *:80>
  ServerName salixdev.ru
  ServerAlias www.salixdev.ru
  DocumentRoot /srv/web/salixdev.ru

  <Directory /srv/web/salixdev.ru>
    Options Indexes FollowSymLinks
    AllowOverride All
    Require all granted
  </Directory>

  # Proxy for mox of web
  ProxyPass /mox-mail/ http://127.0.0.1:1080/webmail/
  ProxyPassReverse /mox-mail/ http://127.0.0.1:1080/webmail/

  ProxyPass /mox-admin/ http://127.0.0.1:1080/admin/
  ProxyPassReverse /mox-admin/ http://127.0.0.1:1080/admin/

  ErrorLog ${APACHE_LOG_DIR}/salixdev.ru_error.log
  CustomLog ${APACHE_LOG_DIR}/salixdev.ru_access.log combined
</VirtualHost>



Устанавливаем утилиту для сертификатов
apt install certbot python3-certbot-apache

Получаем сертификат для каждого сайта

certbot --apache -d salixdev.ru -d www.salixdev.ru
certbot --apache -d salixfab.ru -d www.salixfab.ru

nano /etc/apache2/sites-available/salixdev.ru-le-ssl.conf

<VirtualHost *:443>

    # ... остальные настройки ...

    ProxyPassReverse /mox-admin/ http://127.0.0.1:1080/admin/

    # КРИТИЧЕСКИ ВАЖНО: перезаписываем путь в cookie

    # Прокси для веб-почты
    ProxyPass /mox-mail/ http://127.0.0.1:1080/webmail/
    ProxyPassReverse /mox-mail/ http://127.0.0.1:1080/webmail/
    ProxyPassReverseCookiePath /webmail/ /mox-mail/
</VirtualHost>

Почта
У почты такая система: почта ассоциируется с ip. На ip должен указывать базовый
домен. Если на сервере несколько доменов, то выбираем тот, который будет базовым.
Проверяем, что все записи mx всех доменов указывают на базовый домен.
Добавляем реверсивную запись ip->базовый_домен.
Я выбрал базовым salixdev.ru, соответственно почта mail.salixdev.ru Все записи
mx должны указывать на mail.salixdev.ru Реверсивная запись тоже должна на него указывать.
Убеждаемся в наличии A записи mail.salixdev.ru->ip

# 1. Создаем пользователя mox с домашней директорией
sudo useradd -m -d /srv/mox mox

# 2. Переходим в его домашнюю папку
cd /srv/mox

# 3. Скачиваем последнюю версию mox (для Linux/amd64)
wget -O mox https://beta.gobuilds.org/github.com/mjl-/mox@latest/linux-amd64-latest/dl

# 4. Делаем файл исполняемым
sudo chmod +x mox

# 5. Сразу делаем пользователя mox владельцем
sudo chown mox:mox mox

#Установить правильное имя hostname
hostnamectl set-hostname mail.salixdev.ru

#Отредактировать /etc/hosts
127.0.0.1 localhost
#Вот эта важная строка ip domen
178.212.13.179 mail.salixdev.ru mail

#Установить утилиты для проверки dns
apt install dnsutils
nslookup mail.salixdev.ru
#Должно показать IP
nslookup 178.212.13.179
#Должно показать IP в реверсивном порядке и домен
systemctl restart systemd-hostnamed

#Установить unbound

#Правим resolv.conf
cp /etc/resolv.conf /etc/resolv.conf.backup

# Переключаемся на пользователя mox
